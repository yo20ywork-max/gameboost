# 真正能「加速各種遊戲」的做法

## 核心原理

市售遊戲加速器本質上是節點網路 + 路由策略 + 客戶端體驗，不是神奇演算法。

```text
玩家電腦 -> 加速節點 -> 遊戲伺服器
```

它會有效的情況：

- 玩家 ISP 到遊戲伺服器的跨國路由差。
- 晚上尖峰時段某些 peering 擁塞。
- 原路由掉包，但經過中繼節點比較穩。
- 玩家要連不同國家/地區伺服器。

它不會有效的情況：

- 玩家家裡 Wi‑Fi 就掉包。
- 玩家路由器或數據機品質差。
- ISP 到玩家家裡最後一哩不穩。
- 遊戲伺服器本身爆滿。

## 如何支援「各種遊戲」

### 1. 全流量模式

`AllowedIPs = 0.0.0.0/0`

優點：

- 幾乎所有遊戲都能用。
- 不需要知道遊戲伺服器 IP。
- 最適合 MVP 與早期商用。

缺點：

- 連一般網頁也會走節點。
- 若節點品質差，可能反而變慢。

### 2. 遊戲分流模式

只把遊戲伺服器 IP/CIDR 走節點。

優點：

- 對玩家日常上網影響小。
- 更像成熟產品。

缺點：

- 很多遊戲 IP 會變。
- 有些遊戲使用 CDN、登入、聊天、配對、遊戲 server 多組 endpoint。
- Windows 內建路由表主要按 IP，不是按遊戲 process；若要做 process split tunnel，需要 WFP/driver 等更高階技術，成本與上架難度大幅增加。

## 本專案的實作選擇

- 初版用 WireGuard：成熟、效能好、維運簡單。
- App 提供 full / split / auto。
- split profile 支援 CIDR 與 domain；domain 在玩家電腦連線前解析，避免 geo-DNS 解析錯區。
- 不做封包修改、不做 process injection、不碰遊戲反作弊。

## 真正商用的節點策略

台灣玩家優先：

- Tokyo
- Seoul
- Hong Kong
- Singapore
- Los Angeles / San Jose / Seattle

測試時每個玩家要記錄：

- ISP：中華、台哥大、遠傳、社區網路、校園網路
- 遊戲名稱與伺服器地區
- 原始 ping / jitter / loss
- 加速後 ping / jitter / loss
- 節點供應商
- 時段
- 主觀體感

若某個節點對 70% 以上測試者有改善，再擴容；否則換供應商或換城市。
